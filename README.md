## Что это и зачем

Когда AI-агент работает с проектом через OpenCode, он получает в контекст содержимое `AGENTS.md`. Проблема в том, что разработчики часто кладут в AGENTS.md **всё подряд** — архитектуру, code style, CI-таблицы, списки файлов, историю решений. Файл раздувается до 500–600 строк, из которых в каждый конкретный момент нужны от силы 50. Остальное — шум, который жрёт токены и отвлекает агента.

Этот шаблон решает проблему через **ленивую загрузку**: AGENTS.md содержит только ядро (что это за проект, как собрать, ключевые компоненты), а всё детальное знание — в тематических файлах, которые подгружаются только когда задача требует.



### Словарь `type` в этом шаблоне
OKF не регистрирует типы централизованно, но для консистентности внутри
одного проекта полезно придерживаться фиксированного набора. В шаблоне
используются:
| `type` | Файл |
|--------|------|
| `project-context` | `AGENTS.md` |
| `architecture` | `_concepts.md` |
| `setup` | `_setup.md` |
| `worklog` | `_worklog.md`, `WORK_LOG.md` |
| `backlog` | `_backlog.md` |
| `decision-log` | `_decisions.md` |
| `templates` | `_templates.md` |
| `codestyle` | `_codestyle.md` |
| `ci` | `_ci.md` |
| `troubleshooting` | `_troubleshooting.md` |
| `commands` | `_commands.md` |
| `files` | `_files.md` |
| `glossary` | `_glossary.md` |
| `security` | `_security.md` |
| `analysis-index` | `analysis/index.md` |
| `finding` | `analysis/<file>.md` |
| `project-summary` | `PROJECT_SUMMARY_<issue>.md` |
| `playbook` | `PLAYBOOK_<issue>.md` |
| `pr` | PR description |
Потребители (в т.ч. агент) должны толерантно относиться к неизвестным
`type` — это требование OKF. Но производители (мы) стараются не плодить
новые без нужды.
